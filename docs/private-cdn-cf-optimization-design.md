# 私有化高防可信 CDN 与 CF 链路优化系统完整设计方案

> 保存时间：2026-02-12
> 用途：后续实施、评审与拆分开发任务参考

## 一、核心技术栈选型

- **主控端 (Control Plane)：PHP 8.x + MySQL 8.x + Redis (可选)**
- **优势：** PHP 在开发拥有复杂关系逻辑的管理后台、API 接口及与外部服务（如各大 DNS 提供商 API）对接时，开发效率极高且生态极其成熟。配合 MySQL 能够完美处理海量节点日志、超载记录和证书状态。建议采用高并发常驻内存框架（如 Webman 或 Laravel Octane），以应对多节点高频的心跳上报。

- **被控端 (Data Plane / Node)：Golang 1.21+**
- **优势：** 编译为单一二进制文件，无依赖，完美契合“一键拉取部署”需求。Go 原生强大的并发模型（Goroutine）和内存安全特性，是开发毫秒级 7 层代理网关的最佳选择。

- **通信协议：** HTTP/RESTful API（采用双向 API Key 鉴权）+ WebSocket（用于实时控制台日志下发）。
- **运行系统：** 仅支持 Debian 12（通过 Systemd 守护进程）。

## 二、架构与数据流向设计

### 1. 流量转发链路

`真实用户` ➡️ `智能 DNS CNAME (根据权重解析)` ➡️ `被控端节点 (国内/优质线路)` ➡️ `被控端伪装 SNI 并维持 Keepalive 长连接池` ➡️ `Cloudflare 优选 IP` ➡️ `源站`

### 2. 配置与状态同步链路

- **配置下发：** 主控端面板修改任何配置（新增域名、修改 CF IP、更新证书）➡️ 触发被控端 API ➡️ 被控端内存热更新（立即生效）并写入本地磁盘快照。
- **状态上报：** 被控端每 3-5 秒采集本机 CPU、内存、实时带宽占用、总消耗流量 ➡️ 上报至主控端 API。
- **异常熔断：** 被控端发现某个 CF 优选 IP 连续 Ping 失败 3 次 ➡️ 自动在本地内存中剔除该 IP ➡️ 异步通知主控端。

## 三、核心功能模块详细设计

### 模块 A：主控端 Web 管理后台 (PHP/MySQL)

这是系统的“大脑”，负责所有策略的制定与调度。

1. **大盘监控 (Dashboard)**
   - 汇聚所有在线节点的 CPU、内存、带宽，采用环形图展示（基于轮询上报的数据）。
   - 预警横幅系统：从 MySQL 读取告警日志，页面顶部常驻红色警告横幅，点击进入列表查看详情（时间、节点、超载原因：如 CPU > 90% 或带宽跑满），可执行“忽略”或“标记已读”。

2. **节点管理与智能 DNS 调度**
   - 支持新增节点配置（设定 IP、SSH 端口、最大物理带宽上限）。
   - **DNS 动态权重控制中心：** 主控端后台运行一个定时任务（Cron/Worker）。根据节点上报的资源使用率计算健康分。如果某节点 CPU/带宽超过阈值，主控端直接调用 DNS API（如 Cloudflare、阿里云 DNS），降低该节点 IP 的解析权重；若流量耗尽（剩余 < 10%）或离线，立即暂停解析。

3. **流量计费与配额控制**
   - 设定单向/双向计费逻辑。
   - 月底/月初清零逻辑。流量超限时，主控下发封禁指令，同时自动在 DNS 端停用该节点。

4. **证书中心 (Let's Encrypt DNS-01)**
   - 使用 PHP 集成 ACME v2 协议。
   - **流程：** 提交域名 -> 主控生成 TXT 记录 -> 界面提示用户去修改 DNS -> 用户点击验证 -> 主控拉取证书 -> 通过 API 下发到所有 Node 内存并持久化 -> Node 即刻开始使用新证书。
   - **临期提醒：** 距到期 5 天，Dashboard 飘红预警。

### 模块 B：被控端转发引擎 (Golang)

这是系统的“肌肉”，要求极简、极速、无状态（可随时抛弃并用快照恢复）。

1. **内存级热重载 (Hot Reloading)**
   - **不使用配置文件的 reload！** 所有白名单域名、证书文件流、CF 优选 IP 列表全部加载在 Go 的 `sync.RWMutex` 保护的内存 Map 中。
   - 主控端调用接口推来新配置时，直接更新内存变量。旧的 HTTP 请求不受影响，新的请求瞬间走新配置。

2. **7层反向代理核心 (Reverse Proxy)**
   - **强校验：** 请求到达，首步提取 HTTP Host/SNI，比对内存白名单。不匹配直接强制断开 TCP 连接（返回 444），防止恶意耗流。
   - **IP 透传：** 拦截请求，强制注入/覆盖 `X-Forwarded-For`、`X-Real-IP` 头信息为客户端真实 IP。
   - **WebSocket 劫持：** 识别 `Upgrade` 头，支持全双工通信透传。

3. **连接池与加速优化 (Keepalive & HTTP/2)**
   - 重写 Golang 的 `http.Transport`，维持与 Cloudflare 优选 IP 的长连接池。
   - 重写 `DialTLS`，确保握手时向 CF 发送的 SNI 是真实被访问的域名，否则 CF 会拒绝响应。

4. **单机防刷与安全防护 (Rate Limiter)**
   - 内置轻量级令牌桶算法，防止单 IP 恶意发包耗尽优质线路流量。
   - 支持从主控获取“全网黑名单 IP”并实施内存级拦截。

## 四、部署与系统级调优（一键脚本）

要求在纯净 Debian 12 系统上执行一行 Bash 命令完成所有工作，即装即用。

### 一键脚本业务逻辑

1. **环境准备：** `apt-get update`，安装必要基础组件（curl、wget、ca-certificates）。
2. **拉取程序：** 从 GitHub（私有仓库通过 Personal Access Token）`wget` 预编译好的 Golang 二进制文件。
3. **内核调优 (Sysctl)：** 脚本自动写入以下配置并执行 `sysctl -p`。
   - 开启 `tcp_bbr` 拥塞控制（跨国传输必备）。
   - `fs.file-max = 1048576`（解除文件句柄限制，支撑高并发）。
   - `net.ipv4.tcp_tw_reuse = 1`（快速回收 TIME_WAIT 连接，防止端口耗尽）。
4. **注册 Systemd 服务：** 生成 `.service` 文件，设置开机自启，并自动捕获标准输出和错误日志（便于排查）。
5. **鉴权绑定：** 脚本执行时要求输入主控端 URL 和 `Node_Secret_Key`，启动后被控端立即向主控报到并拉取最新配置。

## 五、异常与灾备设计（容错机制）

1. **主控端宕机/失联**
   - **Node 自治：** 被控端每次收到主控配置，都会在本地 `/etc/proxy-node/config.json` 加密写入快照。与主控失联时继续使用内存数据工作；若被控端重启，则从本地快照读取配置恢复。

2. **DNS 记录未及时生效**
   - 若节点因超载被移出 DNS 记录，但由于用户本地 DNS 缓存仍有流量涌入，此时节点流控模块（如剩余流量 < 10%）做硬性拦截，返回 `503 Service Unavailable`，彻底切断流量消耗。

3. **CF 优选 IP 大面积失效**
   - 若被控端发现当前负载均衡池中的 CF IP 全部宕机（Ping 不通），触发回退机制，尝试请求预设备用 CF Anycast IP（如 `1.1.1.1`），确保业务尽最大可能不中断。

## 六、建议补充：域名维度统计报表

建议增加“域名维度”统计，并至少包含以下视图：

- 24h / 7d / 30d 的域名带宽、请求数、4xx/5xx、命中线路（节点/CF IP）趋势。
- 每个域名 TOP 客户端地区、TOP URL、异常状态码占比。
- 域名级配额与成本估算（按计费规则回放，便于对账）。
- 告警联动：单域名突增、异常错误率、回源失败率升高时自动告警。

这样可以把“节点健康视角”进一步扩展到“业务域名视角”，对运营和故障定位更有价值。
